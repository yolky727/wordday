WORDDAY / SETUP / 3.3

用电脑，连接你的好友系统。

前端仍部署在原 GitHub Pages。Supabase 负责账号、好友、房间与服务器战斗判定。第一次配置完成后，朋友直接使用你的网站即可。

开始前

  1. 在旧站「个人 → 设置 → 数据与备份」导出完整备份。
  2. 解压 3.3 更新包。根目录的 index.html 与 JS/CSS 放回原仓库原路径；backend 是后端部署源文件，不会自动部署到 Supabase。
  3. 刷新网站，确认底部显示 3.3。暂时打开好友入口显示“等待连接”是正常的。

本机单词、表达、卡牌存档不会因为注册账号而上传或被空账号覆盖。好友休闲对战使用导入的本机卡牌阵容；不计入单机奖励或排行榜。

创建一个 Supabase 项目

  1. 在电脑打开 Supabase Dashboard，注册或登录，创建项目。
  2. 项目名可用 WORDDAY；数据库密码自行设置并保存，不需要发给任何人。
  3. 选择你和朋友实际可访问的地区。创建后，先确认两个人的网络都能访问该项目地址；地区近不代表一定可达。
  4. 项目设置中找到 Project URL 和 Publishable key（旧版也可使用 anon key），稍后填入前端。

前端只能填公开 key。Secret key、service_role key、数据库密码和账号登录令牌都不能放入前端或发到聊天中。

建立数据库

  1. 打开项目左侧 SQL Editor，新建查询。
  2. 用记事本或 VS Code 打开更新包 backend/01_database.sql，复制全文粘贴，点击 Run。
  3. 成功后应存在 wd33_profiles / wd33_friends / wd33_rooms / wd33_invites 四张表。脚本已启用 RLS，浏览器不能直接读取这些表。

不需要给 anon 或 authenticated 增加公开读写策略。对手完整手牌只保存在服务器，服务器按规则返回可见信息。

部署对战函数：推荐用网页编辑器

  1. 打开 Edge Functions → Deploy a new function → Via Editor。
  2. 函数名称必须是 wordday-online。
  3. 用电脑编辑器打开 backend/03_wordday-online.ts，复制整个文件替换默认代码，再部署。文件已经包含战斗引擎、卡牌数据与好友服务，不需要拼接其他文件。
  4. 该函数使用自行校验登录的模式：将网关的 Verify JWT / Enforce JWT verification 关闭。界面措辞可能不同；此设置仅针对这个函数。
  5. 函数仍会对每次请求调用 Supabase Auth 校验用户 Bearer token；没有有效登录的请求会返回 401。并非开放匿名数据库访问。

函数在服务器使用平台提供的 SUPABASE_URL 和 SUPABASE_SERVICE_ROLE_KEY。不要把服务器 key 复制到网站；若环境提示缺失，在函数环境设置中检查，勿使用公开 key 代替。

可选：使用电脑终端部署

电脑先安装官方 Node.js LTS；在解压目录打开终端：

cd backend
npx supabase login
npx supabase functions deploy wordday-online --project-ref YOUR_PROJECT_REF --no-verify-jwt

把 YOUR_PROJECT_REF 替换为项目编号（通常是 Project URL 中 .supabase.co 前的一段），登录凭据只在你的电脑或官方页面操作。目录内的 supabase/config.toml 和函数文件已经准备好。不需要启动本地数据库。

设置邮箱登录回跳

  1. 打开 Authentication → URL Configuration。
  2. Site URL 填你的网站主页：https://yolky727.github.io/wordday/。
  3. Redirect URLs 加入同一个完整地址。若实际使用自定义域名或其他路径，也加入对应地址。
  4. 启用 Email 邮箱登录，并保留邮箱验证。首次注册后需要点击邮件中的链接，再登录。

收不到邮件时检查垃圾箱、地址拼写和 Auth 日志。平台发信有额度限制；多人使用时按官方说明配置自己的 SMTP。无需为此关闭邮箱验证。

把公开配置填回网站

打开根目录 online-config.js，只修改这两处：

window.WDOnlineConfig = {
  url: 'https://YOUR_PROJECT_REF.supabase.co',
  publishableKey: '你的 Publishable key 或 anon key',
  functionName: 'wordday-online'
};

保存并上传覆盖 GitHub 仓库中的同名文件。等待 Pages 发布后重新打开网站。配置文件采用联网优先读取；首次配置建议在线重新打开页面。

进入「个人 → 好友与联机」应出现邮箱和密码输入框。若仍显示等待连接，先直接查看站点的 online-config.js 是否已更新，检查引号、URL 与 key 类型。

用电脑和手机验收一场

  1. 电脑注册账号 A，手机注册账号 B，分别验证邮箱并登录。
  2. 两端都在同一个网站域名与路径使用。电脑若没有收藏，可先通过完整备份导入自己的旧存档，或收集至少四种卡牌。
  3. A 复制 8 位好友码，B 输入并发送申请，A 接受。
  4. A 创建房间并邀请 B；B 在好友列表接受邀请，或输入 6 位房间码。
  5. 各自选择进阶卡，剩余位置自动随机补齐；双方点“准备开战”。
  6. 轮到自己时点击出牌；亮牌后选择技能或跳过。服务器处理倒计时、技能次数和胜负。
  7. 完成四回合；平分则加赛。测试手机切后台、关闭重开后，能否从好友页恢复原房间。
  8. 再测试猛犸象的额外技能机会、独角兽禁用、霸王龙两种技能和长颈龙侦察。

联机首版通过约 2 秒一次的请求同步；切后台时暂停请求，返回后恢复。断线不暂停全局倒计时；超时由服务器在下一次请求时执行自动行动。双方都离线时，恢复连接后继续处理。房间 6 小时后过期。

出现问题，按现象检查

  • Failed to fetch / 连接失败：检查项目 URL、网络可达性、函数名称和部署状态。
  • 401：先退出重登；检查网关 JWT 设置与函数 Auth 日志。
  • 数据库操作失败：确认 SQL 已运行，四张表存在，函数环境变量齐全。
  • 409 / 对局刚更新：属于并发保护，等待最新界面后再操作，勿反复连续点击。
  • 房间已过期：创建新房间；旧本地学习与收藏不会受影响。
  • 邮件链接打开别的地址：检查 Site URL 与 Redirect URLs。

反馈时可以给我错误文字和已遮挡敏感信息的页面截图。不要发密码、Secret key、service_role 或 access_token。
